# Ruta crítica y holgura de un proyecto de simulación

**Curso:** 0724 Teoría de Sistemas 2  
**Ciclo:** Segundo semestre de 2026  
**Autor:** Daniel Eduardo Izas Marroquín  
**Tipo:** Ejemplo demostrativo con solución

## Resultado de aprendizaje

Calcular la duración y la ruta crítica de una red pequeña, explicar la holgura y analizar qué cambia cuando una actividad se retrasa. Tiempo sugerido de estudio: 15 minutos.

## Caso y supuestos

Un equipo prepara un modelo de simulación de población estudiantil. Debe completar cuatro actividades. Los datos son ficticios y se utilizan únicamente para aprender el método.

Se cuenta desde el instante 0 en días de trabajo. Las dependencias son fin a inicio, sin esperas adicionales. Hay recursos suficientes para ejecutar A y C en paralelo. El proyecto termina cuando concluyen B y D. No se aplican otras restricciones de fechas ni nivelación de recursos.

| ID | Actividad | Predecesora | Duración en días |
|---|---|---|---:|
| A | Preparar datos del modelo | Inicio | 3 |
| B | Construir el modelo de simulación | A | 4 |
| C | Diseñar las pruebas | Inicio | 2 |
| D | Preparar el informe de validación | C | 3 |

```text
          A (3) --> B (4)
Inicio --<              >-- Fin
          C (2) --> D (3)
```

## Paso 1 Calcular las fechas tempranas

El inicio temprano (ES) de una actividad es el mayor fin temprano (EF) de sus predecesoras. Para las primeras actividades, ES = 0.

```text
EF = ES + duración
A: ES = 0; EF = 0 + 3 = 3
B: ES = 3; EF = 3 + 4 = 7
C: ES = 0; EF = 0 + 2 = 2
D: ES = 2; EF = 2 + 3 = 5
Fin del proyecto = máximo(7, 5) = 7
```

## Paso 2 Calcular las fechas tardías y la holgura

Usamos el día 7 como fin del proyecto para el recorrido hacia atrás. El fin tardío (LF) de una actividad es el menor inicio tardío (LS) de sus sucesoras.

```text
LS = LF - duración
Holgura total = LS - ES = LF - EF
```

| ID | ES | EF | LS | LF | Holgura total |
|---|---:|---:|---:|---:|---:|
| A | 0 | 3 | 0 | 3 | 0 |
| B | 3 | 7 | 3 | 7 | 0 |
| C | 0 | 2 | 2 | 4 | 2 |
| D | 2 | 5 | 4 | 7 | 2 |

## Paso 3 Interpretar el resultado

El camino Inicio-A-B-Fin dura 7 días y el camino Inicio-C-D-Fin dura 5. La ruta crítica es A-B: determina la terminación más temprana calculada bajo los supuestos indicados.

C y D tienen 2 días de holgura total cada una. Este margen se comparte dentro del camino: no son 2 días independientes para cada actividad. Si C utiliza los 2 días, D pierde ese margen cuando se recalcula la red.

## Paso 4 Analizar un cambio

Si D pasa de 3 a 6 días:

```text
Camino A-B = 3 + 4 = 7 días
Camino C-D = 2 + 6 = 8 días
Nueva duración del proyecto = 8 días
Nueva ruta crítica = C-D
```

El retraso de D consume los 2 días de margen del camino y desplaza el fin del proyecto 1 día. La ruta crítica debe revisarse cuando cambian duraciones, dependencias o avances. Si el camino C-D durara exactamente 7 días, habría dos rutas críticas.

## Ejercicio de comprobación

1. ¿Qué ocurre si B aumenta a 5 días y las demás duraciones conservan sus valores iniciales?
2. ¿Qué ocurre si C y D aumentan 1 día cada una respecto del caso inicial?
3. ¿Por qué no basta elegir como críticas las actividades que parecen más importantes?

### Respuestas orientativas

1. A-B dura 8 días; el proyecto dura 8 y C-D tiene 3 días de margen total.
2. C-D dura 3 + 4 = 7 días. Ambos caminos duran 7: hay dos rutas críticas.
3. La criticidad temporal depende de la red, las duraciones y las restricciones. La importancia del contenido por sí sola no determina la fecha de terminación.

## Aplicación en el laboratorio

Trasladar esta lógica al cronograma del equipo, verificar responsables y recursos, conservar la línea base y comparar los avances contra ella. Si un recurso debe atender actividades simultáneas, revisar su disponibilidad antes de aceptar el resultado del cálculo.
